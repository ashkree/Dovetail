# M1 review and retro

Review of the M1 commit (`5521eaf`, workspace, `dovetail-api` and `MockCore`) with `/code-review`, Standards and Spec axes run separately. The `pre-m1` tag predates the spike-results merge, so the review was scoped to the M1 commit; the spike docs were reviewed with S1–S4. Date: 2026-11-03.

**Result:** no hard standards violations, nothing in the spec missing. 7 findings fixed, 8 left open for you (5 need a decision).

## Retro

**Went well**
- Test-first on the reducer gave a clean red (22 failing) then green, and the serde and mock seams caught nothing late.
- Reading the dump by eye found two mock bugs that the consistency tests could not: a finished turn left slices "needs you" forever, so activity stalled; and background subagents never spawned.
- The end-to-end replay test (3,000 events with commands mixed in, client equals core) is the strongest check and cost little.

**Went badly**
- Running M1 and M2 as parallel sessions failed: sessions can't be started over Remote Control. The work ran here instead, serially.
- The `pre-m1` tag sits before the spike-results merge, so every review from it includes the spike docs unless scoped by hand.
- The replay test first failed for a test reason, not a code one: it compared before delivering messages the core had already produced.
- The glossary wasn't checked against field names before writing types; the review caught `priority`.

**Change for M2**
- Add a liveness test to the mock: within a few hundred events, each event kind appears. It would have caught both dump bugs.
- Check new public names against `GLOSSARY.md` before writing them.
- Answer the five open naming and data-model calls above before M2 builds on these types.
