# M2 review and retro

Review of the M2 commit (`f78ff9c`, TUI shell: Layout B, keymap, task tree, inbox) with `/code-review`, Standards and Spec axes run separately. The `m1` tag predates the M1 docs merge, so the review was scoped to the M2 commit. Date: 2026-11-03. Nobody was watching: clear-cut findings were fixed, everything else is listed under Decisions needed with a recommendation.

**Result:** no hard standards violations. Checks: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace` pass (see the final count in the run summary). `cargo tree -p dovetail-tui` shows only `dovetail-api` among Dovetail's crates. One pty run of the real binary covered quit, panic and idle CPU (see the plan's M2 boxes).

## Retro

**Went well**
- The `App` is plain state with no terminal in it: keys in, commands out, and a `TestBackend` render, so 33 behaviour tests ran without a pty. One pty run then covered the three terminal-only boxes.
- The liveness test, asked for by the M1 retro, paid for itself at once: it found four mock gaps the consistency tests could not.
- Degrading the right-hand column by width (status, memory, cost) fixed the clipped names that the 80-column snapshot showed immediately.

**Went badly**
- Several choices the docs leave open (sort order, inbox order, what clears a finished turn) came up mid-build. They are recorded below, but each is a UX call made without you.
- A mock tweak shifts its seeded stream, so a threshold in the liveness test ("within 600 messages") needed re-tuning twice. Message counts are dominated by streamed deltas; a count of plans would be steadier.
- `tree.rs` grew to 660 lines in one go.

**Change for M3**
- Keep reading code to the spec's wording before choosing a default, and list every default in Decisions as it is made, not at the end.
- Build `conversation.rs` as separate parts from the start (markdown to lines, reading column, buffer), so each is testable alone and no file passes about 400 lines.
- Pin the liveness test to a count of plans or virtual time rather than raw messages.

## Decisions needed (with the default used)

1. **Tree order (D1).** Default: Now keeps your own order (`J`/`K` move tasks there); Next, Later and Unsorted sort by P-level, then order. The brief says "sorted by P-level within each bucket" and also "an order within Now"; these conflict in Now. Recommend keeping.
2. **Inbox order (D2).** Default: blocked questions, permission requests, other questions, errors, finished turns; newest first within each. No doc says. Recommend keeping.
3. **Task glyph (D3).** Default: a task shows ⚠ while any of its agents has any inbox item, finished turns included (glossary: "an item here"). b.png shows the opposite for a task whose slice has a pending question. Recommend keeping the glossary reading.
4. **Status bar counts (D4).** Tasks = not done, not archived; agents = sessions not done (subagents excluded); ⚠ = items in Needs you. Recommend keeping.
5. **Widths (D5).** Left column 38 % of the screen, at least 40 columns, at most half; inbox takes the lower 40 % of it. Recommend keeping.
6. **Seen marker (D6).** A coordinator-created task is marked seen when the tree cursor lands on it. M4's task detail may be the better trigger. Recommend: also on opening the detail.
7. **Finished-turn clearing (D7).** Cleared on opening the agent, and while the Main region has focus on that agent's conversation. Recommend keeping; the coordinator you are reading never fills the inbox.
8. **Quit (D8).** `:q` asks only if a session is mid-turn; `:q!` skips the question; quit sends `end_sessions: true` because v1 has no daemon (B23).
9. **Typing prompts (D9).** Reason, reply, title and new-task input use Insert mode on a row under the status bar. Chat input moves to the conversation pane in M3.
10. **Add task (D10).** `a` asks for a title only, lands in Unsorted. M4's quick capture takes over the key's fuller form.
11. **Background subagent progress (D11, data model).** The model has tool count and last tool, no fraction, so the tree shows `12 tools · Grep` instead of b.png's 62 % bar. Recommend keeping: Claude Code reports no fraction.
12. **Confirm key (D12).** The quit confirmation reads `y` directly. Recommend a `Confirm` mode in the keymap table in M4, when the TOML seam matters.
13. **Region names in actions (D13).** Recommend resolving "the inbox's region" and "the main region" through the region table when splits arrive (v2).
14. **Mock changes (D14).** Finished subagents are pruned after one (was two), the coordinator files follow-ups, permission requests can be withdrawn, a messaging warning comes and goes. All driven by the liveness test.
15. **`:panic` (D15).** Debug builds only; it exists so the terminal-restore box can be checked.
16. **Markers (D16).** `≠` for a P-level and bucket mismatch, `✦` for coordinator-created, `↳#n` for follow-up of task n. Visible names are yours to change.
