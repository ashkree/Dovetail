# Ship the decision log and `log_decision` in v1

Refines Decision 25, which places the `log_decision` tool in v1.1, and plan section 7 item A4, which left the decision log out of v1's task detail. The user grills plans often, and each grill settles decisions that would otherwise live only in a conversation transcript. So the decision log ships in v1: entries are stored with the task at M5 (`decisions` table), shown in the task detail newest first, added by hand with `:decide <text>` or `a` in the task detail, and filed by agents through `log_decision` at M9, served by `dovetail mcp` beside `ask_user` and `report_status`. Each entry holds its task, time, author (the user or an agent), the decision in one line, an optional why, and the alternatives considered, each with an optional reason it lost. Entries are append-only: a later entry can supersede an earlier one, which then shows dimmed and struck through with a pointer to its replacement. Slices file on their own task by default; the coordinator must name a task, and the tool returns an error without one. Only the coordinator and slices may call it, as Decision 25's table says. Search over the log stays in v1.1 with the rest of search (Decision 20). Approved by the user on 2026-11-03, in the session that grilled the open calls from the M2 to M4 reviews ([m4 review](../reviews/m4.md#resolved-with-you-2026-11-03)).
